# 骑友计数与「同路骑友」算法说明

## 1. 今日骑行人数(卡片 / 详情页,已上线)

**数据来源**:`ride_records` 骑行记录表 —— 用户点「开始骑行」时自动写入一条。

**统计方式**:后台安全聚合函数 `count_route_riders_today()`(迁移 `0012_route_rider_counts.sql`)
- 按路线分组,统计今天(北京时间)不同用户数(`count(distinct user_id)`)
- `security definer`:绕过行级权限只返回聚合计数,不暴露任何个人记录
- 已授权 `anon` / `authenticated` 调用

**App 接入**:`RoutesView.load()` 调 RPC 填充 `ridersByRoute`;
函数未部署时自动回退旧逻辑(聊天发言去重),页面不会变空。

## 2. 同路骑友(卡片模式 + 路线详情页,已上线)

**页面文案**:定位可用时显示「前往起点路上约有 X 位同路骑友」;
未授权 / 定位失败时回退「今天有 X 位骑友骑行」。
- 卡片模式:按当前轮播卡片实时计算(切卡时重新计算,结果按路线缓存)
- 路线详情页:进页时计算一次
- 列表模式:保持「今天有 X 位骑友骑行」(不做逐行走廊计算)

**数据来源**:`ride_presence`(骑行中每 10 秒上报一次,15 分钟自动过期,公开可读)。

**算法(走廊匹配)**:
1. 我的位置:一次性定位 `OneShotLocationFetcher`(首次唤起系统授权弹窗,仅使用期间)
2. 路线起点:该路线第一个带经纬度的打卡点
3. 走廊:我的位置 → 路线起点 连线,两侧各 200 米
4. 方向代理:骑友比我更接近起点(距起点比我近 +200 米容差),视为同方向
5. 计数:同时满足「在走廊内」+「同方向」的活跃骑友数

**实现位置**:
- 共享算法:`Core/SameWayRiders.swift`(`count` 与 `distanceToSegment`)
- 卡片模式:`RoutesView.swift` 的 `loadSameWay(for:)` + `heatText(_:)`
- 详情页:`RouteDetailView.swift` 的 `loadSameWayRiders()`

**隐私**:只显示「约有 X 位」,不暴露任何骑友的精确位置。
