# 同行人(同路骑士)提醒机制设计(2026-08-22)

> 回答:同行人提醒是什么、有没有弹窗通知、通知形式如何才不影响驾驶。
> 已落地实现:NotificationHelper.swift + RideService.swift。

## 一、触发场景

| 场景 | 数据来源 | 触发条件 |
| --- | --- | --- |
| 同路骑士出现 | ride_presence(骑行中每 10s 上报位置) | 同一条路线出现新骑友(首轮只登记不提醒,避免开场轰炸) |
| 骑行完成 | ride_records 保存成功 | 骑行结束落库 |
| 打卡完成 | ride_checkins 写入 | 打卡点达成(已有开关,可按同分级接入) |

## 二、通知形式分级(核心:骑行中绝不弹窗)

驾驶场景安全第一:摩托车骑行时弹横幅 = 分心 = 事故风险。因此按「是否在骑行中」分级:

| 状态 | 形式 | 说明 |
| --- | --- | --- |
| 骑行中(前台,phase == riding) | 仅短促提示音(系统音 1057,约 0.3s),无横幅、无弹窗、无视觉打断 | companionAlert 前台分支;后续可加耳机语音播报 |
| 后台 / 锁屏 | 系统通知横幅 + 声音(「昵称」正在与你同路骑行) | 锁屏可见,点开进 App |
| App 内非骑行 | 提示音兜底(前台无 delegate 默认不弹横幅) | 不打断当前页面 |

## 三、防打扰设计

1. 开关:设置页已有「同路提示 / 打卡完成 / 骑行完成」开关,默认开启,用户可全关
2. 防轰炸:同一位骑友只提醒一次(按 user_id 去重);骑友消失再出现会再次提醒
3. 开场静默:开始骑行后的第一次检测只记录已有骑友,不提醒
4. 频控:检测轮询 10s 一次;提醒 identifier 固定,系统级去重
5. 建议(1.1 可选):骑行中「语音播报」开关(AVSpeechSynthesizer 播"前方有骑友"),并提示"骑行中建议佩戴耳机"

## 四、现状与后续路线

### 已实现(本次)

- NotificationHelper.companionAlert(riderName:):前台提示音 / 后台系统通知
- RideService 同路检测:新骑友出现 → 触发提醒;结束骑行时重置状态
- 遵守「同路提示」开关

### 后续(1.1,需要 APNs)

- 远程推送:骑友出发/到达 → Supabase Edge Function + APNs 推给同路人(后台也能收到)
- 聊天消息提醒:新消息走同样的「骑行中只提示音」分级
- 实时距离提醒:同路骑友进入 500m 内再提醒(当前是出现即提醒)
- 耳机语音播报与驾驶模式

## 五、测试方法(双设备)

1. A、B 登录两个账号,同选一条路线
2. A 先开始骑行,B 后开始 → B 应听到提示音(前台)或收到系统通知(后台)
3. 切到后台再试一次,锁屏应看到「同路提示」横幅
4. 设置页关闭「同路提示」→ 不再提醒
5. 骑行中确认:无横幅、无弹窗,只有短促提示音
